# Запасы: база данных

Часть проекта «Веб-приложение для учёта домашних запасов». Здесь лежит слой хранения данных: модели SQLAlchemy, готовые запросы и тестовые данные. Он подключается к FastAPI.

## Что готово

- Три модели: `StockItem` (позиция запаса), `Category` (категория), `StorageLocation` (место хранения).
- Защита на уровне БД: количество больше 0, название не пустое, срок годности не раньше даты приобретения.
- Статус срока годности («Годен», «Скоро истекает», «Просрочено», «Срок не указан») и число дней до окончания считаются автоматически от текущей даты и в БД не хранятся.
- Готовые запросы в `app/queries.py`: список с поиском, фильтрами (категория, место, статус), сортировка по названию и сроку годности, статистика для карточек, справочники с количеством позиций.
- Тестовые данные (21 позиция со всеми статусами) и 48 автотестов.

## Как запустить

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt pytest
python -m app.init_db
python -m app.seed --extended
pytest
```

Должно быть `48 passed`. Файл базы `pantry.db` создаётся автоматически и в репозиторий не попадает.

## Для backend

Схема, описание таблиц и пример роутов FastAPI: [docs/DB.md](docs/DB.md).

Как использовать запросы:

```python
from app import queries as q
from app.database import get_db

items = q.list_items(db, q="молоко", category_id=1, status="expiring_soon", sort="expiry")
stats = q.get_stats(db)
```

Что нужно сделать на стороне API:

- Pydantic-схемы для создания и редактирования позиции с понятными сообщениями об ошибках (БД только не даёт сохранить плохие данные).
- Ограничить допустимые значения единицы измерения (шт, кг, г, л, мл, уп).
- Ловить `IntegrityError` при удалении категории или места хранения, к которым привязаны позиции, и возвращать 409 с понятным текстом.

## Вопросы к команде

1. Обязательна ли дата приобретения? В макете она со звёздочкой, в ТЗ нет. Сейчас в БД необязательная.
2. Нужны ли пользовательские иконки продуктов (бутылка, хлеб, яблоко)? Если да, добавим поле `icon` в таблицу позиций.
3. Названия статусов: в UI Kit «Свежий» и «Просрочен», в ТЗ «Годен» и «Просрочено». Сейчас использованы названия из ТЗ.
